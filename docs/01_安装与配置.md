# 01 安装与配置

本包分两部分，**互相独立**，可以只装一部分：

- **Skill**（4 个）：告诉 AI 代理"怎么修"，纯 Markdown + Python 脚本，无需安装依赖。
- **MCP 服务器**（`gsas2`）：让 AI 代理"能动手"，需要 GSAS-II 本体与一个能 import `GSASIIscriptable` 的 Python 解释器。

---

## 1. 环境要求

| 组件 | 要求 | 本包实测环境（打包机） |
|---|---|---|
| 操作系统 | Windows / Linux / macOS | Windows 11 |
| GSAS-II | 官方源码树（git 检出）或已安装版 | `D:\app\xrd\GSAS2-MCP`（含 `GSASII/`） |
| Python | 建议 3.10–3.12（GSAS-II 官方支持范围） | `D:\app\xrd\python.exe`（3.11） |
| MCP SDK | `pip install mcp` | 该解释器内已装 2.0.0 |
| 环境变量 | `GSAS2_MCP_PATH`=GSAS-II 源码树；`GSASII_HEADLESS=true`；`MPLBACKEND=Agg` | 同左 |

> **解释器是最大的坑**：同一台机器上"能 import"不等于"能用"。另有 3.13 环境可以 `import` 但在运行时报
> `Unable to find GSAS-II binaries ... pypowder is not available`，此时峰形计算被静默禁用、wR 数值失去意义。
> 判断标准只有一个：`GSASIIpath.SetBinaryPath(True)` 能报出 `GSASII-bin/win_64_p3.11_n1.26` 之类的二进制目录。

## 2. 三步接入

### 第 1 步：放 Skill

```bash
# Hermes 桌面版（本包实测）
export HERMES_HOME="C:/Users/<你>/AppData/Local/Hermes Agent CN Desktop/data/hermes-home"
cp -r skills/xrd-rietveld "$HERMES_HOME/skills/"
```

其他客户端：Codex 系使用 `~/.codex/skills/`（本包内 `gsas2-xrd-refinement` 的上游文档即以该目录为例，其示例命令中的个人路径已替换为 `~`）；Claude Code / 其他代理按各客户端文档把同一个 `xrd-rietveld/` 目录放进其 skills 根目录即可 —— 目录结构不变（`SKILL.md` + `references/` + `scripts/`）。

### 第 2 步：注册 MCP

**Hermes**：把下面这段并入 `$HERMES_HOME/config.yaml`（片段原文见 `mcp/config/hermes-mcp-config-snippet.yaml`）：

```yaml
mcp_servers:
  gsas2:
    command: D:\app\xrd\python.exe          # ← 改成你的 GSAS-II 解释器
    args:
      - -m
      - gsas2_mcp_server
    env:
      PYTHONPATH: C:\Users\<你>\iPolloWork\gsas2-mcp   # ← 本包 mcp/ 目录所在父路径
      GSAS2_MCP_PATH: D:\app\xrd\GSAS2-MCP            # ← 你的 GSAS-II 源码树
      GSASII_HEADLESS: 'true'
      MPLBACKEND: Agg
    connect_timeout: 180.0
    enabled: true
```

**OpenCode / 其他使用 JSON 的客户端**（原文取自 MCP 自带 README）：

```jsonc
{
  "mcp": {
    "gsas2": {
      "type": "local",
      "command": ["D:\\app\\xrd\\python.exe", "-m", "gsas2_mcp_server"],
      "cwd": "C:\\Users\\<你>\\iPolloWork\\gsas2-mcp",
      "environment": {
        "GSAS2_MCP_PATH": "D:\\app\\xrd\\GSAS2-MCP",
        "GSASII_HEADLESS": "true",
        "MPLBACKEND": "Agg"
      },
      "enabled": true
    }
  }
}
```

**通用三要素**：任何客户端都只需要 `command`（解释器）+ `args`（`-m gsas2_mcp_server`）+ `env`（上表三项）。
把 `mcp/gsas2_mcp_server/` 放进 `PYTHONPATH`（或直接放在 `cwd`）即可，无需 `pip install`。

### 第 3 步：自检

```bash
# ① 工具数应为 19
PYTHONPATH=<本包>/mcp "D:/app/xrd/python.exe" -c "from gsas2_mcp_server import server as S; print(len(S.TOOL_MAP))"

# ② 端到端精修（GSAS-II 官方 PbSO4 样例，不含私有数据）
"<你的GSAS-II解释器>" mcp/examples/e2e_pbso4.py
```

② 会跑完 create → 导入 → 加相 → 设参 → 精修 → 导出，产出 `.gpx` / `*_results.json` / `*_plot.png`。
本包的自检**日志按作者要求不对外**；跑一遍 `mcp/examples/e2e_pbso4.py` 即可得到同样的输出对照。

**MCP 工具需要新会话生效**（改动 config 后重开对话）。

## 3. 排错表（全部为本机实测踩过的坑）

| 症状 | 真实原因 | 处置 |
|---|---|---|
| `ModuleNotFoundError: No module named 'GSASIIpath'` / `cannot import name 'GSASIIscriptable' from 'GSASII'` | 把 GSAS-II **外层**根目录放进了 `sys.path`，于是 `GSASII` 解析成 `GSASII.py` | 放**内层** `GSAS-II\GSASII` 目录进 `sys.path`，再 `import GSASIIscriptable` |
| `*** ERROR: Unable to find GSAS-II binaries ... pypowder is not available` | 解释器能 import 但找不到编译内核（如 Anaconda 3.13） | 换 GSAS-II 专用解释器；任何要读 `.gpx` 的操作（含画图）都必须用它 |
| `NameError: name 'wx' is not defined` | 用错解释器做 GPX 后处理 | 同上 |
| `GSASIIpath.BinaryPath` 不存在 | 属性名不对 | 用 `GSASIIpath.GetConfigValue('GSASII_bin')` |
| wR 一直卡在 ~30%，最强线有大正残差 | 把实测 FWHM² 直接灌进 U/V/W | GSAS-II 的 U/V/W 是**高斯方差**（cdeg²）：FWHM = 2.3548·σ，按 FWHM 灌入要**除以 5.5452** |
| 自由 U/V/W 跑到负值、峰变针状 | 无标定文件时 U/V/W 属探索性 | 未标定就不放开，或只放 W |
| 第二相怎么放都解释不了多余峰 | `add_phase()` 只设相分数初值，refine 标志默认关闭 | 多相时必须 `set_HAP_refinements({'Scale': True})` |
| `SVD problem(s) likely from :0:Scale` 后丢参数 | 直方图标度与相分数同时释放（两者差一个整体自由度，高度相关） | 标度与相分数分开阶段释放 |
| 某相分数塌缩到 ~1e-12、wR=100% | 该相在此数据中**无支撑**（幻影相） | 当作"相不存在"的信号，用 Rf² 二次确认 |
| `Maximum shift/esd` 几十到几百 | GSAS-II 默认迭代轮数太少 | `proj.data['Controls']['data']['max cyc'] = 12` |
| 一个项目失败后，后续全部 `underflow encountered in multiply` | 失败的精修让 numpy 停在报错态 | 每次 `refine()` 前 `numpy.seterr(all='warn')` |
| `TypeError: argument of type 'bool' is not iterable`（Size 等） | HAP 值必须是 dict | `{'Size': {'type':'isotropic','refine':True,'value':0.05}}` |
| 改过的辅助函数仍跑旧逻辑 | 同一 mtime tick 内的 `.pyc` 缓存 | `exec(compile(open(p).read(), p, 'exec'), ns)` 直读源码 |
| `rm -rf` 报 `Device or resource busy` | 当前工作目录就在被删目录里 | 先 `cd` 出去再删 |

更完整的清单（含 CIF 读入陷阱、带电 `_atom_site_type_symbol` 被解析成错误元素、`.lst` 回读、STOE `.asc` 解析）见
`skills/xrd-rietveld/gsas-ii-rietveld-refinement/references/pitfalls-observed.md`（全部为实测复现；本包内为**脱敏版**）。

## 4. 已知缺口（分享时请一并说明）

2. `gsas2-xrd-refinement/SKILL.md` 中的示例命令保留了上游作者的示例路径（已把个人目录替换为 `~`，数据盘符如 `E:\work\...` 保留原样），按需替换。
3. `gsas-ii-multiphase-refinement` 标注 **Beta**，适合已声明相集的科研流程；不替代专家相鉴定。
4. **仪器示例为默认条件（可按需改写）**：包内 Skill 与文档里的仪器示例（STOE WinXPOW `.asc` 解析、
   Cu Kα 波长与 `I(L2)/I(L1)`、扫描栅格 `10/90/0.01°`、`I_MONOCHRO`/`FILTER`）是打包机的默认取值，
   刻意**保留为默认示例**，换仪器/换实验室请按自己的数据文件头逐项改写 —— 见
   `skills/xrd-rietveld/gsas-ii-rietveld-refinement/references/pitfalls-observed.md` §8 的"更改提示"。
   这些默认值与 MCP 的 `GSAS2_MCP_PATH`、解释器路径一样，都属于"装上就能跑自检、跑真数据前要替换"的运行参数。
